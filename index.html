    How does this work without extracting the whole ZIP?

    Every ZIP stores a small central directory (index) at its end. ZipStream downloads only that index (a few KB) using a Range request, lists the files inside, then streams only the byte spans of the file you picked.

    Streaming: a Service Worker exposes each entry as a same-origin "virtual file". When you press Play, the <video> element asks for exactly the byte ranges it needs — a few KB for the header, then more as you watch and whenever you scrub. Stored (uncompressed) entries map 1:1 to ZIP offsets, so seeking is instant and nothing extra is downloaded. Deflated entries are re-inflated on the fly in the worker (DecompressionStream) and stream progressively; a deflate stream has no random access, so seeking far ahead inflates the bytes up to that point.

    Telegram: t.me links are resolved through Telegram's public web preview. Photo posts and direct file links resolve fully. Videos posted as Telegram media can't be streamed from the web preview (they require the Telegram client API, which needs a login/bot token) — the app will tell you what it could and couldn't get.
